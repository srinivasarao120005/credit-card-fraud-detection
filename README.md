# FraudGuard ML | Cost-Aware Transaction Risk Scoring

**Target roles:** Data Scientist / Applied ML Engineer. An end-to-end, leakage-aware fraud risk scoring workflow based on the [ULB/Worldline 2013 credit-card data](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud). Original portfolio repository: https://github.com/srinivasarao120005/credit-card-fraud-detection.

## Business problem and distinct contribution
Fraud makes up a tiny fraction of transactions. Accuracy alone is misleading. This study evaluates supervised XGBoost, Random Forest, and a proposed **risk-budgeted anomaly-fusion policy** combining XGBoost predictions with IsolationForest anomaly ranks, selecting a review budget and fusion weight on the validation period **only**. Contribution is the experimental decision policy, not a claim that XGBoost or IsolationForest is new.

## Dataset, cleaning and leakage controls
- Source: full original `creditcard.csv` from the TensorFlow tutorial mirror (same ULB dataset), downloaded using `src/download_data.py` or manually from Kaggle.
- Audit: schema/labels, missingness, duplicates, invalid amounts, temporal prevalence and class imbalance. See `src/data_audit.py`. Full-row duplicates are **reported**, not silently deleted (repeat transactions may be legitimate).
- Preparation: chronological stable-sort by `Time`, 60% training / 20% validation / 20% test. Model features exclude `Time` and target `Class`; numerical median imputation is fitted **only on training**. `Time` is a coarse elapsed-time value, not account-level event time.
- Training-only class weighting; IsolationForest trained on **legitimate training transactions only**. No SMOTE leakage.
- Candidate fusion weights selected by assumed operational cost on validation; alert budget selected from validation. Frozen decision rule evaluated once on held-out test.

## Reproduce (Python 3.11)
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python src/download_data.py
python run_pipeline.py
python src/predict.py --input data/raw/creditcard.csv --model results/trained_models.joblib --out results/scored.csv
pytest -q
```
Use `--fast` for a quicker smoke run (not intended as the final published benchmark). The normal run creates `results/data_audit.json`, `eda.png`, `metrics.json`, `comparison.csv`, `model_comparison.png`, `trained_models.joblib`.

## Evaluation
PR-AUC (primary ranking metric for imbalance), ROC-AUC, precision, recall, F1/F2, false-positive rate, alerts per 1,000, and cost per transaction under **explicit assumed** `FP=1`, `FN=25` cost units. Change assumed costs for a real business policy. Record test-set comparisons and select no new hyperparameters after viewing test results.

## Known limitations
ULB includes only ~two days of anonymized transactions; it has no customer IDs or verified real-world cost labels. This study demonstrates a temporal holdout, **not** sustained production concept-drift adaptation, business impact, or live fraud performance. Test data are not included in Git.
